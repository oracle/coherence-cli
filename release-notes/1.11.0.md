# Coherence CLI 1.11.0

This release changes management defaults for CLI-created development clusters, local monitoring setup, TLS certificate exceptions, and Linux download verification. Before upgrading from 1.10.14, follow the [upgrade checklist](https://docs.coherence.community/coherence-cli/docs/1.11.0/docs/about/upgrading_1_11_0).

## Local development clusters

* Management over REST binds to `127.0.0.1` by default. The JDK remote JMX connector is disabled unless enabled with `--jmx-port`; when enabled, its registry and RMI connector also default to loopback.
* Running clusters keep their old exposure until restarted. Legacy saved records have no JMX port, so explicitly re-enable JMX if needed. Successful starts save endpoint settings for later use.
* Restart now requires a usable old-member snapshot from the saved REST URL before stopping or replacing JVMs. Unavailable, malformed, empty or invalid membership is an error. Use `start cluster` for an actually stopped cluster.
* Prefer SSH tunnels for remote development access. Intentionally starting non-loopback management requires `--allow-insecure-remote-management` on every applicable invocation, including when using `--yes`. These endpoints remain unauthenticated and unencrypted.
* Use management flags instead of management JVM properties in server arguments, profiles or Java option environment variables. See [Creating Clusters](https://docs.coherence.community/coherence-cli/docs/1.11.0/docs/reference/create_clusters) for supported options and advanced restrictions.

These defaults apply to CLI-created development clusters. Ordinary connections to externally managed clusters do not reconfigure those servers. Metrics, health, user code and custom providers require separate configuration and review.

## Local monitoring

New and reinitialized Grafana/Prometheus stacks bind to loopback and use a generated Grafana administrator password. Existing bundles remain usable with warnings until you migrate them.

Save customizations and export needed Grafana UI state **before stopping or reinitializing**. Stop removes containers; initialization replaces the monitoring directory and generates a new password. Reapply required customizations before starting. Retrieve the current password from the protected `monitoring/grafana-admin-password` file under your CLI configuration directory. See [Local Monitoring](https://docs.coherence.community/coherence-cli/docs/1.11.0/docs/reference/monitoring) for the migration sequence and recovery guidance. Prometheus still has no authentication.

## TLS certificate validation

Certificate exceptions are saved per HTTPS connection and apply only to that connection's origin. New connections verify certificates by default. Discovery, downloads, HTTPS proxies and requests to other origins do not inherit a saved exception.

On first startup, a persisted global exception migrates to eligible existing HTTPS connections without explicit choices. The CLI preserves explicit choices, creates a configuration backup, clears the global value, and stops before network access if migration cannot be persisted. Review inherited exceptions with `cohctl get config -v` and remove unnecessary ones with `cohctl set ignore-certs false -c NAME`.

Scripts that formerly ran `cohctl set ignore-certs true` before adding a connection must change. Prefer valid certificates and CA trust; where necessary, use `cohctl add cluster NAME -u HTTPS_URL --ignore-certs`. See the [TLS migration examples](https://docs.coherence.community/coherence-cli/docs/1.11.0/docs/examples/tls_certificate_validation) and [security guide](https://docs.coherence.community/coherence-cli/docs/1.11.0/docs/security/overview).

## Installation and release downloads

The Linux installer verifies the selected binary against the release SHA-256 manifest before making it executable or copying it into place. [Manual Linux and Windows verification](https://docs.coherence.community/coherence-cli/docs/1.11.0/docs/installation/installation) is also available. Same-release checksums detect corruption or mismatched downloads; they are not independent provenance against replacement of both artifact and manifest. The macOS installation script remains pinned to version 1.10.1 and does not include the checksum verification added to the Linux installer.

Release publication replaces archived release actions with a pinned GitHub CLI and validates repository/tag identity, staged assets and downloaded checksums before advancing the release and documentation publication steps.
