== Miscellaneous

=== Overview
This section contains miscellaneous commands for various settings.

* <<version, `cohctl version`>> - displays the CLI version
* <<get-ingore-certs, `cohctl get ignore-certs`>> - displays the saved connection's certificate-validation setting
* <<set-ignore-certs, `cohctl set ignore-certs`>> - sets the selected saved HTTPS connection's certificate-validation setting
* <<get-logs, `cohctl get logs`>> - displays the cohctl logs
* <<get-debug, `cohctl set debug`>> - displays the debug level
* <<set-debug, `cohctl get debug`>> - sets the debug level on or off
* <<get-management, `cohctl get management`>> - displays management information for a cluster
* <<set-management, `cohctl set management`>> - sets management information for a cluster
* <<get-timeout, `cohctl get timeout`>> - displays the current request timeout (in seconds) for any HTTP requests
* <<set-timeout, `cohctl set timeout`>> - sets the request timeout (in seconds) for any HTTP requests
* <<set-color, `cohctl set color`>> - sets color formatting to be on or off
* <<get-color, `cohctl get color`>> - displays the current color formatting setting

[#get-ingore-certs]
==== Get Ignore Certs

include::../../build/_output/docs-gen/get_ignore_certs.adoc[tag=text]

The selected saved HTTPS connection reports `false` (verification enabled) or `true` (a scoped exception).
HTTP reports `n/a`. Use `-c`/`--connection` or the current saved context; no global choice is used.

*Examples*

[source,bash]
----
cohctl get ignore-certs -c development
----
Output:
[source,bash]
----
Current setting: false
----

[#set-ignore-certs]
==== Set Ignore Certs

include::../../build/_output/docs-gen/set_ignore_certs.adoc[tag=text]

*Examples*

[source,bash]
----
cohctl set ignore-certs true -c development
----
Output:
[source,bash]
----
Value is now set to true
----

Use `cohctl set ignore-certs false -c development` to restore verification. Without `-c`, the
current saved context is selected. Missing or unknown saved connections are errors. HTTP connections
reject both `true` and `false`; this command does not create an exception for a future add.
For an initial HTTPS add probe, use valid trust or explicitly supply `add cluster ... --ignore-certs`.

An exception applies only to that saved connection's HTTPS hostname/IP and effective port. Discovery,
other-origin Coherence*Web/health destinations and general downloads remain verified. Stderr warns
before the first bypassed request per connection/origin in each execution; the application log records
every dispatched bypass attempt. Settings-only commands do not warn. See
xref:../security/overview.adoc[Securing CLI Access] for private CA trust, warning frequency and one-time
migration of the old persisted global setting.
